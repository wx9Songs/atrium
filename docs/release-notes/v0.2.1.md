A fix for sessions that went missing from the sidebar, or showed only part of their history.

## What changed

- **Sessions started from Atrium are listed again.** agentsview 0.47 counts a session as a subagent when it has no parent and its prompts came in through the SDK, and leaves it out of its default session list. Every session Atrium starts or continues with a recent Claude Code looks like that, so such sessions dropped out of the sidebar. The hub now reads the list together with child sessions and leaves out only the ones that sit under a parent (continuations after a compaction stay, as before).
- **No more missing stretch in a conversation.** A session opened from a link, or after a reload, could be shown from Atrium's own record of its runs instead of from the archive, because the messages arrived before the session list and the page never looked again. The hub only sends recent runs, so older turns were missing. The page now switches to the archive's full history as soon as it knows the session.

## Updating

Only the hub changed: replace `atrium` on the server and restart it, then reload open pages. Runners and the macOS app are the same as in 0.2.0 apart from the version number.

修复会话从侧栏消失、或者只显示一部分历史的问题。

- **从 Atrium 发起的会话重新出现在列表里**：agentsview 0.47 把“没有父会话、而且消息是通过 SDK 发进来的”会话算作子代理，不放进默认的会话列表。用较新的 Claude Code 时，Atrium 发起或续接的会话都是这样，于是从侧栏里消失了。现在 hub 连同子会话一起读列表，只去掉挂在父会话下面的（压缩后的续接会话照旧保留）。
- **对话里不再缺一段**：从链接打开或刷新页面时，消息比会话列表先到，页面之后不再重新判断，于是只用 Atrium 自己的运行记录拼出对话；hub 只发最近的运行，更早的几轮就缺了。现在一拿到会话信息，页面就改用归档里的完整历史。
- **升级**：只有 hub 有变化，替换服务器上的 `atrium` 并重启，然后刷新已打开的页面。runner 和 macOS 应用除版本号外与 0.2.0 相同。
